## CI edge-challenge policy

Bot Fight Mode remains enabled. The production-check wrapper accepts only HTTP403 with Cloudflare's exact `cf-mitigated: challenge` header as an edge challenge. Only GitHub Actions with the explicit reporting policy may record that as **BLOCKED**, with a visible job warning/summary; it never counts as a public application or OAuth PASS. All ordinary403s, resource-limit503s and application failures still fail. Outside that explicit CI context, blocked checks remain nonzero. The strict public smoke/auth commands are unchanged. A temporary zone-analytics-read-only diagnostic token confirmed the first event and was immediately revoked; no zone-management credential was placed in GitHub. [Official challenge response contract](https://developers.cloudflare.com/cloudflare-challenges/challenge-types/challenge-pages/detect-response/).

Documentation-only pushes run formatting, source scanning, inventory and portable report validation without redeploying the unchanged app. Main code/config pushes and published releases retain the complete Node/native-Cloudflare/browser/Free-limit/deployment pipeline.
