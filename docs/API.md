# HTTP API

All routes live under `src/app/api`. JSON in and out. Mutations (`POST`/`PUT`/`PATCH`/`DELETE` on private data) go through `mutationUser`: same-origin `Origin`, a session, and the `content:<userId>` budget (30/min). Private JSON bodies must be `application/json` (64 KiB default, 1 MiB for comps). Authentication POST bodies are byte-bounded at 64 KiB before dependency parsing; Stripe webhooks at 256 KiB before signature parsing. Errors are `{ error }` with non-disclosing messages; private responses are `Cache-Control: private, no-store`.

**Auth:** pub = public · sess = requires session · owner/member = checked against current DB rows.

**Limits.** Cloudflare requests require the platform-provided client address: 240 requests/minute per address precede render routing and cache hits, and price/history routes share a 20/minute per-address/server request budget. Every actual AODP attempt (including retries and fanout, after cache hits) additionally reserves one of 10/minute per-address/server slots before the shared 50/minute and 250/five-minute regional budgets. Client cookies and forwarded-for headers cannot renew these allowances. Public caller-supplied price IDs must occur in the supported source catalog; that is not current-patch verification. Authentication is 40/minute per trusted Cloudflare address with a 2,400/minute site-wide backstop. Node does not trust arbitrary proxy headers and uses only the larger auth backstop; publicly hosted Node operators must supply appropriate trusted-proxy/edge abuse controls. Signed-in mutations remain 30/minute/user, exports 5/hour, settings 20/minute. Distributed callers can still exhaust finite shared provider capacity; unavailable/stale observations are not substituted with invented prices.

## Older personal records

Timer and saved-scenario GET responses retain their array bodies. Timers return up to100 rows and scenarios up to50 (optionally filtered by kind). When another page exists, the response supplies `X-Next-Cursor`; pass that value as the `cursor` query parameter using `URLSearchParams`. Ordering is descending update time with ID as a stable tie-breaker. The cursor contains ordering information only: every page still requires the current session and applies the same owner/kind filters. Malformed or oversized cursors return400. Deleting the boundary record does not invalidate a cursor. Reload to see records updated above the current boundary.

The timers page, calculator saved scenarios, transport plans and shopping account lists expose explicit controls to load older entries. Existing records remain stored; there is no silent creation cap or replacement of older saves.
