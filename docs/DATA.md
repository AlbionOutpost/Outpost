# Data

Where Outpost's game and market data comes from, how it is loaded, what we may use it for, and the rules that keep it honest.

## Truth rules

These are enforced in code; keep them that way.

1. **No invented numbers.** An observed `0` or missing price is _unavailable_, never free. A manual `0` is allowed and labelled manual. Any missing input makes a calculator result `complete:false` with null totals.
2. **Identity matches exactly.** An observation is used only if item, region, city, quality, side (buy/sell order) and execution all match. Quality alternatives are shown separately with their own city and date, never substituted.
3. **Every observation keeps its own time.** Buy and sell sides carry their own source timestamps (`sell_price_min_date`, `buy_price_max_date`); fetch time is never shown as observation time. Data older than 1 h (or >5 min in the future) is **stale**. Plans keep the oldest timestamp that fed them.
4. **Unknown stays unknown.** Missing IP shows "Not verified"; unlocks, return eligibility and spell inheritance stay null. Don't derive abilities or recipes from names.
5. **Provenance has stages**: imported → schema-valid → reviewed → verified → current-patch verified (`src/lib/catalog/verification.ts`). A new download or a passing parser never promotes a record. Today every dataset is at **imported/schema-valid; zero records are reviewed, verified or current-patch verified.**
6. **Fees are labelled assumptions.** Every sales-tax field starts at **4% (Premium)**, with "Premium 4%" and "No premium 8%" one tap away, and stays editable (owner decision, 8 Nov 2026; `src/lib/albion/sales-tax.ts`). Combined "tax + setup" fields (farming, fishing) start at 4% too. Setup and station fees keep their own defaults (0, laborers 2.5). A saved scenario or link keeps the tax it carries; only new drafts start at 4%. The Black Market board, Profitable crafts and the flipping scanner use the same rule; where a listing is made they start at the 2.5 % setup fee.

The Black Market board and Profitable crafts each spend one price request per selection (≤48 items, `MAX_SCAN_ITEMS`); the page applies cities, tax and budget to that answer, and signed-out answers are edge-cached for 2 min. The watchlist's "since your last visit" marks (lowest sell and highest buy order, each with its city and observation time) stay in the browser (`outpost:watch-seen-v1`, `src/lib/watch-seen.ts`, at most 200 items) and are never sent to the server.

Coverage depends on what players upload: exact-quality gaps are common, especially on Asia and for T8. AODP data is crowd-sourced and has no warranty — the UI must say so where it matters.

**Game Info** (`combat-events.ts`, `combat-source.ts`): `gameinfo.albiononline.com` (+ `-ams`, `-sgp`) events feed, 20 per page, 12/min per region, 45 s cache. Powers the kill/death feed. Game Info sometimes answers with an old copy of the feed (8 Nov 2026: the Asia feed returned kills from 31 Oct minutes after returning that afternoon's), so each answer is dated: the page shows its newest kill's age, and the API marks it `freshness: "snapshot"` when it is over an hour behind the newest kill Outpost has already seen from that server (asked once more first; kept 10 s instead of 45 s) or `"delayed"` when the first page's newest kill is over an hour old. Either way the page says so above the kills; old fights are never shown as the latest. The home page's top kills come from Outpost's own seven-day shortlist, which the data Worker's per-minute cron fills from the live feed and the `killfame?range=week` ranking; that collector also keeps the newest-kill mark the feed compares against. The gear value shown with a kill is an estimate (the worn pieces at their cheapest royal-city sell order) and is labelled as such with the pieces it could not price.

### Loading pipeline

1. `npm run data:prepare-snapshot <dir>` — verifies each slot file's hash against `docs/data/item-snapshot-source.json`, normalizes (`src/lib/catalog/item-snapshot.ts`) and writes the bundle.
2. `npm run data:sync` — loads the bundle into Postgres (`imported` / `already-active`; refuses version or checksum mismatches).
3. `npm run data:source -- --source <config>` — optional reviewed-source pipeline: pinned 40-char commit + SHA-256, raw.githubusercontent only, writes immutable output to `.qa/game-sources/`. Never activates data by itself. `docs/data/ao-source.example.json` intentionally fails closed.
4. `npm run data:audit` — structural audit (duplicates, invalid mappings, bundle hash); writes `.qa/game-data-coverage.json`.
5. Cloudflare: `cloudflare-stage-catalog.mjs` / `cloudflare-stage-library.mjs` export to D1 (see [OPERATIONS.md](OPERATIONS.md#data-pushes-manual)).

The `scripts/import-grind-*` scripts rebuild the archive files from a local `Scrape/` capture that is not in the repository. `import-grind-game-data.py` writes everything under `src/lib/albion/game/` and the hash ledger; captured JavaScript is read as text and transcribed, never run. Where the archive and older Outpost data disagreed, the archive wins: the city table added Caerleon and Brecilien specialties (bags, capes, potions, food, tools, gathering gear, war gloves, shapeshifter staves) and enchanting now uses per-slot rune counts. Every previously bundled recipe matched the archive exactly. albionutil.com data in the same folder is third-party and is not imported.

### Patch updates

On an Albion patch: confirm the official patch name/date, diff the pinned old/new source records, list affected IDs, recipes, icons and calculators, mark them stale, and re-run calculator fixtures before activating. Keep the previous revision until the new one is reviewed.

## Rights and licensing

- **Item snapshot:** MIT — fine to use with the retained notice.
- **ao-bin-dumps:** public, but **no declared license**; we use only minimal factual recipe fields (materials and quantities). Redistribution rights and patch compatibility are unconfirmed — an owner decision is open.
- **albiononlinegrind.com archive:** the owner's own capture; treat as historical content and label it so.
- **AODP:** community data, used live with attribution.
- Never copy competitor code, prose or artwork; never scrape authenticated content.

## Team economy (8 November 2026)

Team wallets are a ledger of whole in-game silver (`GroupWalletEntry`): every change keeps who it is for (a member, or the team pot), the signed amount, its kind (credit, debit, payout, reset, split, roll), a reason, who booked it and when. Balances are always summed from the entries, so the ledger and the totals cannot disagree. Coin flips (`GroupCoinFlip`, no stake; they never touch the ledger) and loot rolls (`GroupLootRoll`, one `GroupLootRollEntry` per member) store the server's draw with its time. A team's guild tax (`Group.guildTaxPercent`, 0–100 with one decimal, default 0, set by Manage team) is only shown to members; a loot split stores the rate it applied, and paying the split books that tax to the pot as a `split` entry. None of it is real money: Outpost holds nothing, sells nothing and moves no silver in game, and the UI says so beside every balance. A player's own entries are in their account export; deleting an account removes their entries, flips and rolls, and the team keeps the pot.
