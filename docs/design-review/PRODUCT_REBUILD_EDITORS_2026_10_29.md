## Confirmed data loss and bounded recovery

The real local reproduction changed a private saved composition's title, used browser Back and Forward, and returned to the original saved title. `.qa/product-rebuild-editors/comp-history-before.json` records `lost: true`. This reproduction ran against the actual application on shared dev3006 using an isolated owner session; a prior attempted baseline trial used an invalid empty roster and did not establish behavior.

Composition recovery now reuses the existing `AccountBuildDraftCache` implementation through a default generic payload type. The build cache's default type and behavior are unchanged. Composition entries are document-memory only: no localStorage, sessionStorage or automatic server save. They have the same30-minute lifetime, eight-entry limit,262,144-character ceiling and owner-generation writer lease. A server-authorized editor receives an owner ID and source/region or saved-composition identity. React keys prevent a reused editor from carrying a previous owner/source/region's canonical state into a different context.

Controls remain disabled until actual client handlers and recovery are ready. Committed edits are captured synchronously before unmount. A recovered draft retains its original base revision, so an intervening server update yields the existing409 instead of overwriting newer data. Successful save clears only its matching recovery entry. Confirmed signout clears composition recovery after synchronous cancellation handlers; canceled signout retains it. Full reload closes document-memory recovery and still prompts for unsaved work. Save/export remains the permanent retention action. Denied reads and mutations remain the responsibility of the unchanged server services.
