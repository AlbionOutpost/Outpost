## Composition hydration submission guard

A retained earlier native-Cloudflare CI run (`.qa/site-refinement/prior-recovery-ci-failure.log`,117/118) failed the Add-to-comp save journey: the page changed from the sourced draft URL to `/compositions/new?` then `/compositions/new`, rather than a saved composition. Source review confirmed that the server-rendered form exposed an enabled submit button before its client `onSubmit` handler attached; its default submission method was GET. The existing hydration signal only protected file import.

The composition editor now renders a disabled fieldset until its existing server-false/client-true hydration signal commits, covering Save and every editable control. The form also declares POST so a missed handler cannot put draft fields into a GET URL. A scoped display-contents wrapper preserves the existing layout. The existing source-copy journey now gates real Next client chunk requests, checks the SSR Save is disabled and that native activation leaves the source/title/database unchanged, then releases the chunks and executes the original immediate Save assertions. There is no arbitrary delay or relaxed destination/role/region expectation. Fixed-runtime browser verification is pending the parent's next build; the older CI failure remains recorded.
