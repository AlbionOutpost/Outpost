## Design decisions

The admin area is a quiet working surface rather than another set of illustrated marketing cards: Barlow headings, Inter controls, Geist Mono identifiers, copper selection, charcoal or parchment surfaces and concise administrative language. It has an overview, user search, account detail, review queue, existing content reports and audit pages. Four metrics lead into a real creation chart and content inventory. Chart values also have keyboard/touch inspection and an HTML daily table. Desktop navigation becomes a horizontally scrollable strip on phones; the user table becomes readable stacked account rows, with labelled details links.

Gift and security actions sit beside the account context on desktop and follow it on phones. Reasons are required, pending actions are disabled, success/errors remain visible and ban confirmation includes the exact identity. ADMIN/owner protections are explained. Review signals state their criteria and limitations; no invented risk score, visits, revenue or automatic verdict appears.

The older working-page pass uses smaller title-case headings, existing painted task emblems, bounded readable mastheads, quieter form surfaces, clearer tables and settings spacing. It covers shared page families rather than introducing a separate design system per tool. The recently redesigned gear editor and personal composition directory are explicitly excluded from the shared override. Existing landing cutouts, guide layout, motion, Albion IDs, assets and calculator formulas remain intact. Public activity statistics now say Accounts and count stored users; administrator edits no longer masquerade as player activity.

## Review findings and corrections

1. The initial shared header changes unintentionally affected equipment/composition screenshots. Overrides now exclude pages containing `.gear-studio` and `.composition-directory`; the composition 1440 mismatch disappears without changing its golden.
2. First admin captures exposed small text over the bright skyline and horizontal phone account rows. Opaque quiet header/metric/rail surfaces and stacked rows improve readability. Long names, reasons and identifiers wrap without widening the page.
3. The older Settings menu retained a desktop `top:84px` after becoming relatively positioned on phones, covering the next section heading. The mobile offset is removed; measured navigation/form separation and keyboard/dialog checks verify the correction.
4. Working mastheads inherited `width:100vw` and the dark painted-scene palette after becoming bounded surfaces. Final overrides explicitly restore 100% width, inherited theme tokens and normal heading color/shadow. This was caught by actual light-mode inspection despite the earlier automated axe scans reporting no violations; automated scans were not treated as visual acceptance.
5. Existing content reports initially retained the old bare-on-skyline presentation. It now shares the administrative header and working surface, while the existing moderation permissions/actions remain.
6. Empty chart series now report Peak 0 rather than using the minimum rendering denominator as the observed peak.
7. Broad browser QA exposed a real guest-draft recovery race: a restored clean draft still armed a 700ms autosave and could overwrite a changed storage record. A controlled-clock reproduction failed before the fix. Clean saved/restored drafts no longer schedule that unnecessary write; the original recovery test is preserved and a timing regression added. This is independent of admin entitlements.
8. The first native Firefox harness used an explicit context cookie partition and reached sign-in instead of the fixture admin. The cookie was installed in the default isolated browser context using BiDi; authenticated screenshot headings and native keyboard actions then passed. No failed harness run is labelled authenticated acceptance.
